# Console Compliance Testing

## Что это такое

Compliance testing (cert testing / TRC testing) — проверка соответствия игры **обязательным техническим требованиям платформодержателя** (Sony, Microsoft, Nintendo). Это отдельный вид тестирования, отличный от функционального:

- **Функциональное тестирование** — ищет "баг ли это" относительно требований продукта
- **Compliance testing** — формализованная проверка "прошли/не прошли" по фиксированному чек-листу платформы, часто на сотни пунктов

Если игра не проходит compliance — её не пустят в продажу на консоли. Это жёсткий gate перед релизом, а не опциональная проверка.

## Терминология по платформам

| Платформа | Название требований |
|---|---|
| Sony (PlayStation) | **TRC** — Technical Requirements Checklist |
| Microsoft (Xbox) | **XR** — Xbox Requirements (ранее XDK/TCR) |
| Nintendo | свой checklist |

## Типичные категории требований

Паттерн похож на всех платформах:

1. **Save data (сохранения)** — корректное создание/чтение/обновление сейвов; обработка нехватки места на диске, повреждённых сейвов, отключения накопителя во время записи
2. **Управление лицензией/аккаунтом** — вход/выход пользователя, смена профиля во время игры, обработка потери сетевого соединения
3. **Trophies / Achievements** — корректная разблокировка без дублей, соответствие описаниям
4. **Suspend/Resume** — корректный уход в спящий режим и восстановление (например, по кнопке PS/Xbox)
5. **UI/UX стандарты платформы** — единый стандарт кнопок (например, "какая кнопка = подтверждение"), корректные иконки контроллера
6. **Производительность и стабильность** — отсутствие крашей, соответствие заявленному FPS/разрешению, отсутствие memory leaks при долгой сессии
7. **Легальные требования** — корректное отображение возрастных рейтингов, копирайтов, дисклеймеров

## Важный нюанс: compliance issue ≠ отдельная категория от функционального бага

Compliance issue почти всегда **одновременно** является функциональным багом — просто с дополнительным ярлыком "нарушает конкретный пункт TRC/XR".

На практике это значит:
- В баг-репорте указываются оба аспекта: обычная severity/priority по функциональным критериям **и** отдельная пометка типа "TRC violation" / "compliance blocker"
- Compliance-баги обычно получают жёсткий blocker-статус перед сертификацией, даже если по чисто функциональным критериям баг выглядел бы как minor
