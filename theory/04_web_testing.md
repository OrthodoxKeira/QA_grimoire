# Тестирование веб-приложений: чек-лист областей

# Формы

## 1. UI / Визуальное тестирование

Проверка того, как элементы выглядят и располагаются
* Элементы не наезжают друг на друга, не обрезаются
* Тексты помещаются в отведенное окно 
* Placeholder-текст в полях корректен и исчезает при вводе
* Обязательные поля визуально помечены
* Состояние кнопки: hover, disabled, loading
* Адаптивность - страница правильно подстраивается под разные разрешения экрана

## 2. Функциональное тестирование полей - позитивные сценарии

* При вводе корректных данных, получаем ожидаемый результат (см. требования)
* Отправка формы не только кнопкой, но и Enter (usability)
* Автофокус - курсор сразу в первом полу (usability)
* Табуляция - Нажатие клавишы Tab переключает между полями в правильном порядке (usability)
* Автозаполнение браузера подставляется корректно
* Copy-Paste в поле пароля работает корректно
* Trim-пробелов - ' test@email.com ' обрабатывается как валидный email

## 3. Валидация и обработка ошибок - негативные сценарии

* Пустая форма без введенных данных -> сообщение об ошибке
* Неполлные данные - пропуска каждого поля по очереди -> ошибка на конкретном поле
* Дубликат username или email, который уже зарегистрирован -> ошибка "уже используется"
* Некорректные значения по техникам тест-дизайна
* Клиентская валидация - ошибка показывается мгновенное, до отправки на сервер
* Серверная валидация - Сервер должен повторять клиентскую валидацию. (Можно отключить JS и обойти клиентскую валидацию)

## 4. Usability / UX

* Сообщения об ошибках понятны обычному пользователю
* Ошибка отображается рядом с конкретным полем, а не общим текстом
* Кнопка "Показать пароль", если есть - работает корректно

## 5. Совместимость

* Разные браузеры могут по-разному реднерить форму
* Разные ОС - автозаполнение и рендер шрифтов могут отличаться в заивимости от ОС

## 6. Безопасность

* SQL-инъекции в полях формы
* XSS - ввод **<script>alert(1)</script>** в поле имени; если скрипт выполнится при отображении - критическая уязвимость
* Хэширования пароля в БД - пароль не должен храниться в открытом виде
* HTTPS - форма с паролем передается по защищённому соединению
* Пароль не должен попадать в URL (если форма отправляется методом GET - багулина)

## 7. Проверка через DevTools

* Console - ошибки JS, случайные **console.log** с чувствительными данными
* Network - что уходит в запросе на сервер, какой ответ
* Elements - соответствует ли верстка дизайну, нет ли зашитых в HTML чувствительных данных (пароли, токены, комментарии)

## 8. Работа с сетью

* Поведение при медленном интернете (DevTools -> Throttling)
* Прведение при прерванном соединении во время отправки формы
* Двойной клик на кнопку отправки формы
