# Шаблон: Баг-репорты

## Как заполнять этот шаблон

- **ID** — порядковый номер (BUG-001, BUG-002...)
- **Заголовок** — суть проблемы в одной строке (не "ошибка", а "Кнопка Login не активируется при заполненных полях")
- **Severity** — насколько критичен баг:
  - **CRITICAL** — приложение не работает (крах, потеря данных)
  - **HIGH** — серьёзная функция не работает
  - **MEDIUM** — функция работает, но с проблемами
  - **LOW** — косметические проблемы, опечатки
- **Статус** — NEW (найденный), ASSIGNED, FIXED, WONTFIX
- **Шаги воспроизведения** — точно как воспроизвести проблему
- **Ожидаемое поведение** — что должно быть
- **Фактическое поведение** — что происходит сейчас
- **Окружение** — браузер, ОС, версия
- **Скриншот/видео** — если есть (обычно не будет на начальном этапе)

## Примеры баг-репортов

### BUG-001: Кнопка Submit остаётся активной при пустом поле Email

**Severity:** HIGH

**Статус:** NEW

**Окружение:** 
- Chrome 120.0 (Windows 10)
- https://demoqa.com/forms

**Шаги воспроизведения:**
1. Заходишь на страницу формы
2. Заполняешь поле "First Name" значением "John"
3. Оставляешь поле "Email" пустым
4. Остальные обязательные поля заполняешь корректно
5. Смотришь на кнопку "Submit"

**Ожидаемое поведение:**
- Кнопка "Submit" должна быть неактивной (disabled) или серой
- При клике на кнопку должна появиться ошибка "Email is required"

**Фактическое поведение:**
- Кнопка "Submit" остаётся полностью активной (синяя, кликабельна)
- При клике на Submit форма отправляется без Email
- На сервере возникает ошибка 400

**Дополнительно:**
Это критичный баг валидации. Форма отправляет невалидные данные.

### BUG-002: Текст ошибки обрезается на мобильных устройствах

**Severity:** MEDIUM

**Статус:** NEW

**Окружение:**
- Safari на iPhone 12
- iOS 17.2
- https://demoqa.com/alerts

**Шаги воспроизведения:**
1. Открываешь сайт на iPhone 12 в Safari
2. Нажимаешь на кнопку "Show Alert with Timeout"
3. Ждёшь появления alert сообщения

**Ожидаемое поведение:**
- Весь текст alert сообщения должен быть виден
- Текст должен корректно переноситься на новую строку
- Сообщение полностью читаемо

**Фактическое поведение:**
- Alert появляется с обрезанным текстом
- Последняя часть сообщения не видна (заходит за границы экрана)
- Нет кнопки "OK" для закрытия alert

**Дополнительно:**
Проблема проявляется только на мобильных устройствах. На десктопе всё работает корректно.

### BUG-003: Опечатка в сообщении об ошибке

**Severity:** LOW

**Статус:** NEW

**Окружение:**
- Chrome 120.0 (Windows 10)
- https://demoqa.com/forms

**Шаги воспроизведения:**
1. Открываешь страницу формы
2. Вводишь неправильный email (например, "test@")
3. Нажимаешь "Submit"

**Ожидаемое поведение:**
- Появляется сообщение об ошибке с корректной орфографией

**Фактическое поведение:**
- Появляется сообщение "Invliad email format" (опечатка: "Invliad" вместо "Invalid")

**Дополнительно:**
Чисто косметический баг. Не влияет на функциональность, но портит впечатление от приложения.

### BUG-004: Двойная отправка формы при двойном клике

**Severity:** CRITICAL

**Статус:** NEW

**Окружение:**
- Chrome 120.0 (Windows 10)
- Подключение: 3G (медленный интернет симулирован в DevTools)

**Шаги воспроизведения:**
1. Заходишь на страницу формы
2. Корректно заполняешь все поля
3. Быстро кликаешь два раза на кнопку "Submit"
4. Смотришь консоль браузера и сервер логи

**Ожидаемое поведение:**
- Форма отправляется один раз
- При втором клике кнопка уже неактивна (disabled)
- В логах сервера только одна запись о отправке

**Фактическое поведение:**
- Форма отправляется ДВА раза
- Кнопка "Submit" остаётся активной во время отправки
- В базе создаются два дублирующихся записей
- На сервере логируются две идентичные POST запросы

**Дополнительно:**
Это CRITICAL баг, потому что это может привести к дублированию данных в базе. Нужно либо заблокировать кнопку при отправке, либо добавить проверку на серверной стороне.

## Важные правила при написании баг-репортов

✅ **Делай так:**
- Один баг = одна проблема
- Заголовок конкретный: "Кнопка не работает при..."
- Шаги понятны, что даже новый человек сможет воспроизвести
- Приложи Severity правильно
- Объясни, почему это проблема

❌ **Не делай так:**
- "Форма сломана" — слишком расплывчато
- "Баг в логине" — непонятно что именно
- Забываешь указать окружение (браузер, ОС)
- Шаги вроде "используй форму" — неконкретно
- Severity всегда HIGH (всё критично 😅)

## Что дальше?

1. Скопируй этот файл в свой репо: `manual-qa/bug-reports/TEMPLATE.md`
2. Когда тестируешь приложение, смотри внимательно на ошибки
3. Если найдёшь баг — документируй по этому шаблону
4. Если ничего не найдёшь — это тоже нормально (приложение может быть хорошо сделано)

## Шпаргалка по Severity

| Severity | Пример |
|----------|--------|
| **CRITICAL** | Кнопка Login полностью неработающая, приложение падает, потеря данных |
| **HIGH** | Форма отправляется дважды, важная функция не работает |
| **MEDIUM** | Текст обрезается, есть задержки при загрузке, неправильное сообщение об ошибке |
| **LOW** | Опечатка в тексте, неправильный цвет кнопки, мелкие UI проблемы |
