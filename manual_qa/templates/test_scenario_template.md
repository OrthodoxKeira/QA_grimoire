# 🎬 Шаблон тестового сценария (Test Scenario)

## Что такое тестовый сценарий?

Тестовый сценарий — это **высокоуровневое описание пользовательского пути** (user flow) или бизнес-процесса, который нужно протестировать. В отличие от тест-кейса, не содержит детальных шагов — это скорее **"что проверяем"**, а не "как".

**Соотношение с тест-кейсами:**
```
Тестовый сценарий (1)
 ├── Тест-кейс: позитивный путь
 ├── Тест-кейс: негативный путь (неверный ввод)
 ├── Тест-кейс: граничные значения
 └── Тест-кейс: альтернативный путь
```

## Пример заполненного сценария

### Метаданные

| Поле          | Значение                                              |
|---------------|----------------------------------------------------------|
| **ID**        | TS-005                                                 |
| **Название**  | Регистрация нового пользователя через email            |
| **Модуль**    | Авторизация / Регистрация                              |
| **Приоритет** | 🔴 Высокий                                            |
| **Автор**     | Мария Козлова                                          |
| **Дата**      | 2024-11-01                                              |

### Описание сценария

Новый посетитель сайта хочет создать аккаунт через форму регистрации по email, чтобы получить доступ к личному кабинету и оформлять заказы.

**Актор:** Незарегистрированный пользователь
**Цель:** Создать аккаунт и войти в систему
**Предусловие:** Пользователь не зарегистрирован, открыта главная страница

### Проверяемые аспекты

- [ ] Успешная регистрация с корректными данными
- [ ] Валидация обязательных полей
- [ ] Проверка формата email
- [ ] Проверка сложности пароля
- [ ] Регистрация с уже существующим email
- [ ] Отправка письма подтверждения
- [ ] Активация аккаунта по ссылке из письма

### Связанные тест-кейсы

| ID      | Тип           | Описание                                                |
|---------|---------------|---------------------------------------------------------|
| TC-020  | Позитивный    | Регистрация с валидными данными                         |
| TC-021  | Негативный    | Регистрация с уже занятым email                         |
| TC-022  | Негативный    | Регистрация с невалидным форматом email                 |
| TC-023  | Негативный    | Пароль не соответствует требованиям сложности            |
| TC-024  | Граничный     | Email максимальной допустимой длины (254 символа)        |
| TC-025  | Альтернатив.  | Регистрация через OAuth (Google) как обходной путь        |

### Статус сценария

| Поле                        | Значение           |
|--------------------------------|-------------------|
| **Статус**                  | ⚠️ Частично покрыт |
| **Дата последнего прогона** | 2024-11-10          |
| **Результат**               | Провален            |
| **Открытые баги**           | BUG-091 (письмо не приходит), BUG-092 (нет валидации пароля) |

## Типовые пользовательские сценарии для веб-приложений

Используй как отправную точку при составлении своих сценариев:

| Область             | Примеры сценариев                                                   |
|---------------------|--------------------------------------------------------------------------|
| **Авторизация**     | Вход, выход, восстановление пароля, регистрация                        |
| **Профиль**         | Редактирование данных, смена пароля, загрузка аватара                   |
| **Каталог/Поиск**   | Поиск товара, фильтрация, сортировка, просмотр карточки                 |
| **Корзина**         | Добавление, изменение количества, удаление, применение купона           |
| **Оформление**      | Выбор адреса, способа оплаты, подтверждение, отмена                     |
| **Уведомления**     | Email-уведомление, push, SMS о статусе заказа                          |
| **Администрирование**| Управление пользователями, контентом, заказами                        |

## Советы

> **Сценарий ≠ тест-кейс.** Сценарий описывает «путь пользователя», а тест-кейс — конкретную проверку на этом пути.

> **Начинай с главного пути (Happy Path)**, потом добавляй негативные и граничные кейсы.

> **Один сценарий** может порождать **5–15 тест-кейсов** — это нормально.
