# Основы API-тестирования

# 1. API

API - набор правил и инструкций, по которым два приложения (или модуля внутри одного приложения) могут обмениваться данными.
    Описывает, какие запросы можно отправить, что нужно передать, и что придёт в ответ. 

С точки зрения тестирования, API можно рассматривать как *контракт*. Проверяем соблюдение этого контракта - дайт ли API то, тчо обещано в документации.
Основной инструмент - Postman. 

# 2. HTTP-методы

HTTP-метод - часть запроса, которая говорит серверу, какое действие нужно выполнить с ресурсом

* Get - Поулчить данные - Без тела - Получить профль пользователя
* POST - Создать новую сущность - С телом - Зарегистрировать нового пользователя
* PUT - Полностью заменить сущность - С телом - Обновить все поля профиля
* PATCH - Частично изменить сущность - С телом - Обновить только email в профиле
* DELETE - Удалить сущность - Обычно без тела - Удалить аккаунт

В GET запросе тоже можно передавать данные, но обычно это происходит в самом URL через query-параметры или через headers (напр. токен авторизации)
В POST данные передаются в теле, обычно в формате JSON
PUT ожидает все поля, если какое-то не передано - оно может очиститься
PATCH заменяет переданные поля, остальное не трогает

# 3. Структура HTTP-запроса

Метод - см. выше
Endpoint - конкретный адрес, по которому отправляется запрос
Headers - метаданные запроса: тип контента, токен авторизации, язык, кто отправитель. Есть у всех методов
Body - сами данные, которые передаются на сервер. Обычно JSON
Query-параметры - часть URL в GET-запросе (обычно ?** **=** **)


# 4. Коды ответа

* 2xx - Успех 
    * 200 - ОК
    * 201 - Created
    * 204 - No content (успех, но отвечать нечем, обычно DELETE)

* 4xx - Ошибка на стороне клиента

  * 400 Bad request - запрос некорректен
  * 401 Unauthorized - Не авторизован - нет токена или он невалиден - Я не знаю, кто ты
  * 403 Forbidden - Авторизован, но нет прав на это действие - Я знаю кто ты, но тебе сюда нельзя
  * 404 Not Found - ресурс не найден
  * 429 Too Many Requests - Превышен лимит запросов

* 5хх - Ошибка на стороне сервера
    
    * 500 Internal Server Error - Сервер упал с необработанной ошибкой
    * 502 Bad Gateway - Промежуточный сервер получил невалидный ответ от другого сервера
    * 503 Server Unavailable - Сервер временно не может обработать запрос (перегружен, на обслуживании)
  
# 5. QA в API

Что конкретно проверяем:
* Код ответа соответсвует ситуации
* Структура ответа (JSON) - все ожидаемые поля на месте, правильлные типы данных
* Валидация на урове API - что если отправиль пустой body на POST? Сервер должен повторять клиентскую валидацию, а не доверять ей
* Атовризация - запрос без токена должен вернуть 401, разгарничене доступов
* Время ответа - не превышает ли API оговоренный SLA (напр. 500мс)
